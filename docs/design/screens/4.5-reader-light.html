4. EMPIRICAL EVALUATION AND BENCHMARKING

To systematically assess the veracity of model-synthesized pull request reviews, we formulate three targeted research questions. Prior literature predominantly examines synthetic syntax bugs in isolation [14, 21]. Conversely, our experimental framework emphasizes nuanced domain logic, boundary validation invariants, and multi-file inter-procedural contracts.

4.1 Research Questions & Methodology

RQ1 (Precision & Coverage): To what degree do LLM-driven autonomous code reviewers hallucinate non-existent runtime issues compared to senior human peer reviewers?

RQ2 (Security Invariants): Does retrieval augmentation over project-wide AST embeddings curtail ungrounded security recommendations?

4.2 Dataset Selection and Corpus Construction

Regarding corpus compilation, we targeted high-impact repositories spanning Python, TypeScript, and Rust. Specifying rigorous inclusion metrics, we conduct an extensive empirical study across 12 open-source repos comprising 4,290 merged pull requests and 18,400 associated human review comments. Each reviewed changeset was mirrored locally into isolated container environments to verify build reproducibility and execute test suites against patch revisions.

Data preprocessing removed automated bot commits (e.g., Dependabot, Renovate) and formatting-only changesets using tree-sitter diff sanitization [29]. Review comments were categorized into functional criticisms, styling advice, and non-actionable chatter through multi-annotator agreement metrics (κ = 0.82).

4.3 Comparative Model Setup

We benchmarked GPT-4o, Claude 3.5 Sonnet, and DeepSeek-Coder-V2 against human reviewer ground truth. Prompts adhered strictly to chain-of-thought code reasoning conventions without zero-shot temperature jitter (fixed at τ = 0.1).
